Definition09

What is an agent? [1]

An agent is a system
which uses tools
to interact repeatedly
with its environment
to accomplish its goal.

Not a chatbot, not a single prompt. A loop that acts, observes, and acts again until the goal is reached.

Harness · 2/6 · Instructions15

CLAUDE.md, the rulebook

Every hire reads the internal rulebook on day one, then never asks those questions again. CLAUDE.md is that rulebook for your agent.

# ~/.claude/CLAUDE.md # Who I am Paul, member of the executive team. # How you should behave Do not use em-dashes or other AI tells when writing. # Things you should know All our knowledge is on SharePoint, always check there if unsure.
  • One file, read at every session start, global or per project. [1]
  • Home of everything you'd otherwise repeat in every prompt: context, rules, conventions, commands.
  • Per project, so each agent carries its own ground truth, on top of a global one.
  • Reference: Andrej Karpathy publishes his own CLAUDE.md — a great model to steal from. Link in your starter repo.

Harness · 3/6 · Memory16

Memory, the experience it builds

A hire gets better with every meeting: who is picky, which rules never bend. That experience, the agent writes down and reuses — two rungs, climbed in order.

Level 01 · In the moment Just ask

"remember Muriel reviews every external mail." It holds that for next time.

Level 02 · .txt & .md Write it down

Plain files it edits itself: readable, diffable, versionable — an index up top, one short file per fact, loaded on demand.

# memory/MEMORY.md — an index up top # Memory index Microsoft suite only, never Google Workspace → it-stack.md VP invites need an agenda and one decision → vp.md Muriel reviews every external mail, keep short → muriel.md
Copy — the memory rule
We operate exclusively on Microsoft / Azure. We CANNOT sign with a counterparty that hosts or routes our data on Google Cloud / Google Workspace — doing so is impossible and deleterious.

Why it matters: A culture of written knowledge is the load-bearing asset. What lives only in someone's head, the agent can't use; what's written down, it reads, reuses, keeps current. [1]

Talking to your agent20

A good prompt is a good brief

The four parts
  • Context — what the intern needs before starting: who it's for, what exists already.
  • Task — the one thing you want done, stated plainly.
  • Guidelines — how you like it done: tone, format, sources, examples.
  • Constraints — the hard lines: deadline, length, what must not change.
One real brief, annotated
Context: goes to an exec team, read on their phone between two meetings. Task: summarize the attached 40-page report. Guidelines: lead with the three decisions, plain business language, one source per claim. Constraints: one page max, nothing confidential quoted verbatim.

That is all prompting is: briefing a very fast intern. The structure is a habit, not a ritual — skip it when the ask is obvious.

Context engineering22

What the model actually sees

The context window · rebuilt every turn [1]

System

CLAUDE.md · environment · Skills index (name + description) · Memory index (one line per fact)

Tools

search_web(query) → results · fetch_page(url) → content · read_file(path) → text …

Conversation

Your message · thinking · tool call · tool result (× many) · agent answer · your next message — then free space.

Four ideas
  • One text, stateless — rebuilt and re-sent every single turn. The model remembers nothing by itself.
  • Three zones — instructions, tools, conversation. Everything the agent "is" lives in one of them.
  • Progressive disclosure — indexes up top, detail on demand. Exactly the SKILL.md and MEMORY.md you just saw.
  • A finite window — there's a size limit, so you manage what earns its place.

Method · Step 3 of 428

03  Test and improve

Judge the output you see, push the fix into the skill, re-run, repeat until it's great.

  • Use the skill to improve your output and your workflow.
  • It shows you the rendered output in the live preview and asks what's weak — plain language, no jargon.
  • You react with your taste; it pushes the fix into the skill (not the one-off output), then re-runs so you re-review.
  • Loop until you're happy — every run gets better and the improvement survives the next one.

Data hygiene33

Four reflexes that age well

01 Separate primary from processed

Primary sources on one side, AI-generated outputs on the other, never mixed. Once they blur, you can't trust either.

02 Keep sensitive data out of context

.claudeignore excludes folders from the agent's sight, same spirit as .gitignore.

03 Read-only by default

Reference data is mounted read-only — the agent reads it, never rewrites it.

04 Mind the destination

Sensitive code and data don't leave for non-EU clouds — that's what the sovereign path is for.

LLM as judge35

Never trust one vote

  • An LLM judging an output is noisy: ask the same judge twice, it changes its mind.
  • So sample it 3 or 5 times — an odd number — and take the majority vote. [1]
  • A small law of large numbers, for the price of a few extra calls.

"Is this briefing properly sourced?"

✓ ✓ ✗ ✓ ✗

→ ✓ yes (3 / 5). Five samples, one stable verdict. Use it inside your binary checks whenever a criterion needs judgment.
